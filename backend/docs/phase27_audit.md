## 2. Answers to the 20 Mandatory Audit Questions

### 1. Where is the selected avatar stored?
- In `ProjectDocumentV1.scenes[i].avatar.avatar_id` (a string reference storing the UUID or canonical identifier of an `Avatar` record from the PostgreSQL `avatars` table).
- Defined in [project_document.py](file:///d:/HeyGen/video-ai-tools/backend/app/schemas/project_document.py#L41-L53).

### 2. Where is the selected voice stored?
- In `ProjectDocumentV1.scenes[i].speech.voice_id` (a string reference storing the voice identifier, e.g., `"en_US-lessac-medium"`, `"en_US-bryce-medium"`, or `"af_heart"`).
- Defined in [project_document.py](file:///d:/HeyGen/video-ai-tools/backend/app/schemas/project_document.py#L55-L62).

### 3. Where is the generated speech Asset stored?
- Stored as an audio file in MinIO under `workspaces/{workspace_id}/assets/audio/...` (e.g., MIME `audio/wav`), tracked in the PostgreSQL `assets` table (`asset_type="audio"`), and referenced in `ProjectDocumentV1.scenes[i].speech.audio_asset_id` (as well as cataloged in `ProjectDocumentV1.assets`).
- Synthesized by `ProjectSpeechOrchestrator` ([project_speech_service.py](file:///d:/HeyGen/video-ai-tools/backend/app/services/project_speech_service.py)).

### 4. Where is the avatar video Asset stored?
- Stored as an MP4 video file in MinIO under `workspaces/{workspace_id}/assets/video/...` (MIME `video/mp4`), tracked in the PostgreSQL `assets` table (`asset_type="video"`), and referenced in `ProjectDocumentV1.scenes[i].avatar.video_asset_id` (as well as cataloged in `ProjectDocumentV1.assets`).
- Generated by `ProjectAvatarOrchestrator` ([project_avatar_service.py](file:///d:/HeyGen/video-ai-tools/backend/app/services/project_avatar_service.py#L204-L235)).

### 5. How does a Scene reference its avatar?
- Via `scene.avatar` (`SceneAvatar` schema model in [project_document.py](file:///d:/HeyGen/video-ai-tools/backend/app/schemas/project_document.py#L41-L53)):
  - `avatar_id: str` — foreign reference to `avatars.id`
  - `look_id: Optional[str]` — optional outfit / pose look reference
  - `position: Dict[str, float]` — canvas transform `{ "x": 0.5, "y": 0.65, "scale": 1.0, "rotation": 0.0 }`
  - `view_mode: str` — framing mode (`"half_body"`, `"close_up"`, `"circle"`)
  - `video_asset_id: Optional[str]` — synthesized talking-avatar video asset ID in MinIO

### 6. How does the compositor discover the avatar video?
- In `TimelineCompositor._render_scene_clip` ([compositor.py](file:///d:/HeyGen/video-ai-tools/backend/app/media/compositor.py#L249-L266)):
  ```python
  if scene.avatar:
      av_ref = scene.avatar.video_asset_id or getattr(scene.avatar, "asset_id", None)
      if av_ref:
          avatar_path = await mws.resolve_asset(asset_id=av_ref, workspace_id=workspace_id, db=db)
  ```
  If `avatar_path` exists on disk, the compositor extracts probe metadata and routes into the multi-track avatar video compositing branch.

### 7. How does lip-sync receive the speech audio?
- In `ProjectAvatarOrchestrator.generate_project_avatar_video` ([project_avatar_service.py](file:///d:/HeyGen/video-ai-tools/backend/app/services/project_avatar_service.py#L149-L161)):
  - Resolves `speech_audio_uuid = uuid.UUID(target_scene.speech.audio_asset_id)`.
  - Fetches the `Asset` record from `AssetRepository`.
  - Retrieves raw audio bytes from MinIO via `storage.get_object(speech_audio_asset.storage_key)`.
  - Passes `audio_bytes=speech_audio_bytes` directly to `avatar_provider.synthesize_avatar_video(...)` or `LipSyncContractRequest`.

### 8. Which lip-sync provider is currently production-capable on CPU?
- **None**. Neither CPU lip-sync engine is marked production-commercial:
  - `Wav2LipONNXAvatarProvider` runs on CPU using ONNX Runtime (CPUExecutionProvider), but is strictly classified as **Research-Only / Non-Commercial** (`commercial_permitted: False`, `research_only: True`, `license_classification: "RESEARCH_ONLY"`) due to its training on the LRS2 dataset ([wav2lip.py](file:///d:/HeyGen/video-ai-tools/backend/app/ai/adapters/wav2lip.py#L122-L141)).
  - `MockAvatarProvider` is a deterministic testing double.
  - Thus, Wav2Lip provides a **real CPU prototype / development** capability, but cannot be claimed as a commercial production provider.

### 9. Which lip-sync provider requires CUDA?
- `MuseTalkAvatarProvider` ([musetalk.py](file:///d:/HeyGen/video-ai-tools/backend/app/ai/adapters/musetalk.py#L82-L165)).
  - Requires `requires_gpu=True`, `supported_devices=["cuda"]`.
  - Enforces `self._ensure_cuda_available()`, failing immediately on non-CUDA hosts.

### 10. How does GPU admission prevent CPU fallback?
- In `AIProviderRegistry.get_provider` ([registry.py](file:///d:/HeyGen/video-ai-tools/backend/app/ai/registry.py#L149-L170)):
  - Directly inspects `detect_hardware().has_cuda`.
  - If requested device is `"cuda"` or provider is `"musetalk"` and `not hw.has_cuda`, immediately raises `AIRuntimeUnavailableException(code="GPU_UNAVAILABLE")`.
- In `MuseTalkAvatarProvider._ensure_cuda_available()` ([musetalk.py](file:///d:/HeyGen/video-ai-tools/backend/app/ai/adapters/musetalk.py#L153-L165)):
  - Checks `detect_hardware().has_cuda` and raises `AIRuntimeUnavailableException(code="GPU_UNAVAILABLE")`.
- In `AIProviderRegistry` ([registry.py](file:///d:/HeyGen/video-ai-tools/backend/app/ai/registry.py#L208-L218)):
  - When `settings.AI_PROVIDER_MODE == "real"`, resolving a mock provider without an explicit `"mock"` override raises `AIRuntimeUnavailableException(code="REAL_MODE_MOCK_FALLBACK_FORBIDDEN")`.
  - No fallback handler intercepts `GPU_UNAVAILABLE` to secretly route to CPU.

### 11. Is Wav2Lip currently intended as production or research/prototype?
- **Research / prototype only**.
  - Documented in adapter docstrings and descriptor: `license: "Research Only (LRS2 Non-Commercial)"`, `commercial_permitted: False`.
  - Documented in Model Registry ([model_registry.py](file:///d:/HeyGen/video-ai-tools/backend/app/ai/model_registry.py#L885-L913)): `model_id="avatar/wav2lip-cpu"`, `license_classification="RESEARCH_ONLY"`, `commercial_use_permitted=False`.

### 12. Is MuseTalk currently executable on the available hardware?
- **No**.
  - The live host hardware verified by `app.cli.gpu validate` is an AMD Ryzen 5 5500U CPU with integrated AMD Radeon Graphics (0.5 GB VRAM), lacking NVIDIA CUDA acceleration.
  - CLI Output: `GPU_UNAVAILABLE: No NVIDIA GPU detected on host (vendor=AMD, model=AMD Radeon(TM) Graphics)`.
  - MuseTalk weights are also not installed. Any execution attempt yields `GPU_UNAVAILABLE`.

### 13. Does the existing scene pipeline support an avatar video Asset?
- **Yes**.
  - `ProjectDocumentV1.SceneAvatar` contains `video_asset_id: Optional[str]`.
  - `ProjectAvatarOrchestrator` updates `target_scene.avatar.video_asset_id` and adds the asset reference to `doc.assets`.
  - `TimelineCompositor` probes and composites this video asset when rendering.

### 14. Can the compositor combine avatar video + speech audio?
- **Yes**.
  - In `TimelineCompositor._render_scene_clip` ([compositor.py](file:///d:/HeyGen/video-ai-tools/backend/app/media/compositor.py#L335-L441)):
    - If `avatar_path` exists, it layers the avatar video over the background canvas (using either circular PIP filter or neural alphamerge matting).
    - It attaches the speech audio file via `-i {speech_audio_path}`.
    - It maps the audio track via `-map {audio_idx}:a:0` with `-c:a aac -b:a 192k -ar 48000 -ac 2`.
    - It outputs a synchronized, composited scene MP4.

### 15. Does project versioning preserve avatar + speech configuration?
- **Yes**.
  - `ProjectAvatarOrchestrator` and `ProjectSpeechOrchestrator` deep-copy the `ProjectDocumentV1` before modifying.
  - Concurrency is guarded by checking `project.revision == expected_revision`.
  - A new immutable `ProjectVersion` is committed with incremented revision number and `source="avatar_video"` or `source="speech_synthesis"`.
  - Unmodified scenes, speech settings, and visual layers remain byte-for-byte intact.

### 16. Does localization preserve/reset avatar and voice correctly?
- **Yes**.
  - In `ProjectLocalizationService.translate_project` ([project_localization_service.py](file:///d:/HeyGen/video-ai-tools/backend/app/services/project_localization_service.py#L90-L111)):
    - Avatar identity and visual framing (`scene.avatar.avatar_id`, `view_mode`, `position`) are preserved.
    - Generated media references are safely reset: `scene.avatar.video_asset_id = None` and `scene.speech.audio_asset_id = None`, because the old lip-sync video was baked to source-language phonemes.
    - Script is translated and voice is remapped to the target language voice.

### 17. What happens if avatar access is denied?
- `AvatarRepository.get_by_id` ([avatar.py](file:///d:/HeyGen/video-ai-tools/backend/app/repositories/avatar.py#L20-L41)) filters by `(Avatar.workspace_id == workspace_id OR Avatar.visibility == "public")`.
- If an avatar is private to another workspace, `get_by_id` returns `None`.
- `AvatarService.get_avatar` raises `NotFoundException(code="AVATAR_NOT_FOUND", message="Avatar not found in this workspace.")`.
- The caller receives HTTP 404 / structured error, preventing any data leak or cross-workspace access.

### 18. What happens if avatar is unavailable?
- If the avatar UUID does not exist or has been soft-deleted (`deleted_at is not None`), `AvatarService.get_avatar` raises `NotFoundException(code="AVATAR_NOT_FOUND")`.
- If the avatar exists but lacks reference image assets (`source_asset_id` and `preview_asset_id` are `None`), `ProjectAvatarOrchestrator` raises `NotFoundException(code="AVATAR_IMAGE_ASSET_MISSING")`.

### 19. What happens if lip-sync generation fails?
- If inference fails (e.g., face detection failure, corrupted audio, ffmpeg error), the exception propagates.
- No new `ProjectVersion` is written to PostgreSQL, keeping the project revision uncorrupted.
- In Celery asynchronous execution ([ai_tasks.py](file:///d:/HeyGen/video-ai-tools/backend/app/workers/tasks/ai_tasks.py#L258-L275)), `_execute_lip_sync` catches the error, sets the job status to `failed`, records structured diagnostic details (`code`, `error`, `provider`), and calls `service.mark_failed`.

### 20. What happens if GPU is unavailable?
- When requesting a GPU provider (e.g., `musetalk` or `device="cuda"`):
  - Hardware admission detection runs immediately.
  - Raises `AIRuntimeUnavailableException(code="GPU_UNAVAILABLE")`.
  - In Celery jobs, the task transitions to `failed` with `error_details={"code": "GPU_UNAVAILABLE", ...}`.
  - It NEVER generates fake MP4s or silently falls back to CPU.

## 3. Existing Codebase Architecture Review

### Avatar Data Flow
```
1. Avatar Selection:
   Avatar (DB table: avatars) -> Workspace Scoped or Public
   ↓
2. Project Document:
   ProjectDocumentV1.scenes[i].avatar: SceneAvatar(avatar_id="<uuid>", view_mode="half_body", ...)
   ↓
3. Speech Dependency:
   ProjectDocumentV1.scenes[i].speech: SceneSpeech(voice_id="<id>", script="...", audio_asset_id="<asset-uuid>")
   ↓
4. Neural Lip-Sync:
   ProjectAvatarOrchestrator -> Retrieves Avatar reference image + Speech audio WAV from MinIO
   -> Executes LipSyncProvider (Wav2Lip ONNX on CPU)
   -> Ingests output MP4 into MinIO as video Asset
   -> Updates scene.avatar.video_asset_id
   -> Commits new immutable ProjectVersion under OCC
   ↓
5. Timeline Compositing:
   TimelineCompositor -> Resolves scene.avatar.video_asset_id and scene.speech.audio_asset_id
   -> Multi-track FFmpeg composite (avatar overlay + background canvas + audio muxing)
   -> Rendered project MP4
```
